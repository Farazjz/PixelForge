     1→     1→# Master Development Prompt: PixelForge AI — Windows Pixel Art Studio
     2→     2→
     3→     3→## 1. Project Overview
     4→     4→
     5→     5→Act as a senior desktop software engineer, pixel-art editor developer, UI/UX designer, and AI integration specialist.
     6→     6→
     7→     7→Build a professional Windows desktop application named **PixelForge AI**, a pixel-art creation studio that combines a powerful manual pixel-art editor with AI-assisted generation and editing.
     8→     8→
     9→     9→The application must allow users to:
    10→    10→
    11→    11→1. Create pixel art manually from a blank canvas.
    12→    12→2. Generate pixel art using natural-language prompts and an external or locally hosted AI model.
    13→    13→3. Import AI-generated images and convert them into clean, editable pixel art.
    14→    14→4. Refine, recolor, animate, and export pixel art using traditional editing tools.
    15→    15→5. Connect their own AI API endpoint, API key, and model, without depending on a proprietary AI provider.
    16→    16→
    17→    17→The result must be a real, working Windows desktop application, not merely a mockup or UI prototype.
    18→    18→
    19→    19→### Core product philosophy
    20→    20→
    21→    21→- Manual editing must work without an internet connection or an AI API.
    22→    22→- AI must be optional and provider-independent.
    23→    23→- All generated pixel art must be editable on a pixel-by-pixel basis.
    24→    24→- Preserve sharp pixel edges without unwanted blur or antialiasing.
    25→    25→- Prioritize performance, usability, and a polished desktop experience.
    26→    26→- Prefer free and open-source libraries and avoid mandatory subscriptions.
    27→    27→
    28→    28→## 2. Target Platform and Technology Stack
    29→    29→
    30→    30→Build the application primarily for Windows 10 and Windows 11, x64.
    31→    31→
    32→    32→Recommended technology stack:
    33→    33→
    34→    34→- **Desktop framework:** Tauri 2.
    35→    35→- **Frontend:** React + TypeScript.
    36→    36→- **Build tool:** Vite.
    37→    37→- **UI styling:** Tailwind CSS with a consistent component system.
    38→    38→- **State management:** Zustand or an equivalent lightweight solution.
    39→    39→- **Pixel canvas rendering:** HTML Canvas 2D or a suitable WebGL renderer.
    40→    40→- **Image processing:** Rust backend where appropriate, plus browser-compatible image-processing libraries.
    41→    41→- **Local persistence:** SQLite for project metadata and settings, with local file storage for project assets.
    42→    42→- **Project format:** A documented native project format containing layers, palettes, frames, metadata, and image data.
    43→    43→- **Testing:** Vitest for frontend logic and Playwright or an appropriate desktop testing solution for end-to-end tests.
    44→    44→
    45→    45→Use compatible, maintained dependencies. If Tauri introduces excessive complexity for the development agent, Electron with React and TypeScript is an acceptable fallback. Do not mix the two frameworks.
    46→    46→
    47→    47→The final application must be packaged as a Windows installer or a portable Windows executable.

   103→   103→## 4. Manual Pixel-Art Editor

   105→   105→This is the primary functionality and must work independently of AI.
   106→   106→
   107→   107→### 4.1 Canvas creation
   108→   108→
   109→   109→Allow custom canvas dimensions, including presets:
   110→   110→
   111→   111→- 8 × 8
   112→   112→- 16 × 16
   113→   113→- 32 × 32
   114→   114→- 48 × 48
   115→   115→- 64 × 64
   116→   116→- 96 × 96
   117→   117→- 128 × 128
   118→   118→- 256 × 256
   119→   119→- 512 × 512
   120→   120→
   121→   121→Users must also be able to enter custom width and height.
   122→   122→
   123→   123→Include presets for:
   124→   124→
   125→   125→- Game sprites.
   126→   126→- Characters.
   127→   127→- Tilesets.
   128→   128→- Icons.
   129→   129→- Game objects.
   130→   130→- Backgrounds.
   131→   131→- Textures.
   132→   132→- Isometric assets.
   133→   133→
   134→   134→Canvas size and zoom must remain separate properties.
   135→   135→
   136→   136→### 4.2 Drawing tools
   137→   137→
   138→   138→Implement the following tools:
   139→   139→
   140→   140→1. Pencil — draw individual pixels.
   141→   141→2. Eraser — erase pixels to transparency.
   142→   142→3. Paint Bucket — fill connected areas with a selected color.
   143→   143→4. Fill All — replace a selected color across the image or layer.
   144→   144→5. Line — draw straight pixel lines.
   145→   145→6. Rectangle — outline or filled rectangles.
   146→   146→7. Ellipse — outline or filled ellipses.
   147→   147→8. Eyedropper — sample a pixel color.
   148→   148→9. Color Picker — choose exact RGBA or HEX values.
   149→   149→10. Selection — rectangular selection and move.
   150→   150→11. Lasso Selection — optional advanced selection.
   151→   151→12. Move — move selected content or layers.
   152→   152→13. Pan — move the viewport.
   153→   153→14. Text — render text into a pixel-art layer using a selected font and rasterization settings.
   154→   154→15. Gradient — optional, with dithering and limited-palette options.
   155→   155→16. Dithering Brush — optional advanced shading tool.
   156→   156→
   157→   157→All drawing tools must respect the active layer and selection.
   158→   158→
   159→   159→Support mouse input and pressure sensitivity where feasible, without making pressure-sensitive hardware mandatory.
   160→   160→
   161→   161→### 4.3 Pixel-art quality tools
   162→   162→
   163→   163→Implement:
   164→   164→
   165→   165→- Bresenham-style pixel line rendering.
   166→   166→- Crisp nearest-neighbor scaling.
   167→   167→- Optional constrained line angles.
   168→   168→- Symmetry drawing: horizontal, vertical, and both axes.
   169→   169→- Pixel-perfect cleanup options.
   170→   170→- Optional 1-pixel outline generation.
   171→   171→- Palette reduction.
   172→   172→- Color replacement.
   173→   173→- Flood-fill tolerance settings for imported raster images.
   174→   174→- Nearest-neighbor resize.
   175→   175→- Nearest-neighbor rotation and flipping.
   176→   176→- Sprite cropping.
   177→   177→- Image trimming.
   178→   178→- Checkerboard transparency preview.
   179→   179→
   180→   180→Never silently blur or smooth the canvas during ordinary drawing or pixel-art export.
   181→   181→
   182→   182→### 4.4 Editing operations
   183→   183→
   184→   184→Support:
   185→   185→
   186→   186→- Undo and redo.
   187→   187→- Cut, copy, and paste.
   188→   188→- Duplicate layer.
   189→   189→- Duplicate selection.
   190→   190→- Flip horizontally and vertically.
   191→   191→- Rotate 90 degrees.
   192→   192→- Crop to selection.
   193→   193→- Resize canvas without resizing artwork.
   194→   194→- Resize artwork with selectable nearest-neighbor scaling.
   195→   195→- Clear layer.
   196→   196→- Merge down.
   197→   197→- Flatten image.
   198→   198→- Select all.
   199→   199→- Deselect.
   200→   200→- Lock and hide layers.
   201→   201→
   202→   202→Undo/redo must handle drawing strokes as coherent operations rather than creating one history entry per pointer movement.
   203→   203→
   204→   204→Use an efficient history system that avoids storing a complete duplicate of the entire document after every pixel change.
   205→   205→
   206→   206→### 4.5 Layers
   207→   207→

   209→   209→

   211→   211→- Layer names.

   213→   213→- Locking.
   214→   214→- Reordering.
   215→   215→- Opacity.
   216→   216→- Duplicate.
   217→   217→- Delete.
   218→   218→- Merge down.
   219→   219→- Grouping if practical.
   220→   220→- Layer thumbnails.

   226→   226→
   227→   227→Implement:
   228→   228→
   229→   229→- Built-in pixel-art palettes.
   230→   230→- Custom palette creation.
   231→   231→- Palette import and export.

   242→   242→## 5. AI Studio: Generate Pixel Art from Prompts
   243→   243→
   244→   244→AI integration is a major product feature.
   245→   245→
   246→   246→The user must be able to enter a natural-language prompt, configure generation settings, and generate images using their own AI service.
   247→   247→
   248→   248→Example prompt:
   249→   249→
   250→   250→> Create a 32x32 pixel-art red mushroom with a cream-colored stem, dark outlines, a limited 12-color palette, transparent background, and a retro RPG style.
   251→   251→
   252→   252→The AI interface must include:
   253→   253→
   254→   254→- Prompt input.
   255→   255→- Optional negative prompt.
   256→   256→- Width and height.
   257→   257→- Art style.
   258→   258→- Palette constraints.
   259→   259→- Transparent background preference.
   260→   260→- Outline preference.
   261→   261→- Level of detail.
   262→   262→- Seed, when supported.
   263→   263→- Number of results, when supported.
   264→   264→- Generate button.
   265→   265→- Cancel button where the provider supports cancellation.
   266→   266→- Progress and error messages.
   267→   267→- Generation history.
   268→   268→- Preview gallery.
   269→   269→- Import into editor.
   270→   270→- Save generated image.
   271→   271→- Regenerate and vary options.
   272→   272→
   273→   273→Include suggested prompt templates for:
   274→   274→
   275→   275→- RPG characters.
   276→   276→- Enemies and monsters.
   277→   277→- Weapons and equipment.
   278→   278→- Food and collectibles.
   279→   279→- Buildings.
   280→   280→- Trees and plants.
   281→   281→- Terrain tiles.
   282→   282→- Isometric objects.
   283→   283→- UI icons.
   284→   284→- Animated sprite concepts.
   285→   285→- Game backgrounds.
   286→   286→
   287→   287→### 5.1 AI-generated image requirements
   288→   288→
   289→   289→Do not assume that an image-generation model can generate exact pixel dimensions, transparent backgrounds, or perfectly aligned pixel grids.
   290→   290→
   291→   291→Instead, implement a robust processing pipeline:
   292→   292→
   293→   293→1. Send the prompt to the configured provider.
   294→   294→2. Receive an image or image URL, depending on the provider response.
   295→   295→3. Decode the image safely.
   296→   296→4. Resize or resample to the target canvas dimensions using nearest-neighbor scaling when appropriate.
   297→   297→5. Offer color quantization to a specified palette size.
   298→   298→6. Preserve alpha transparency when supported.
   299→   299→7. Provide an optional transparent-background removal workflow.
   300→   300→8. Offer edge cleanup and pixel-art outline processing.
   301→   301→9. Display the processed result for review.
   302→   302→10. Allow the user to import the result as a new layer, replace the current layer, or create a new document.
   303→   303→
   304→   304→Never overwrite existing artwork without explicit confirmation.
   305→   305→
   306→   306→Provide a before/after preview so users can compare the original generated image with the pixel-art-converted version.
   307→   307→
   308→   308→### 5.2 AI-assisted editing
   309→   309→
   310→   310→Support an AI-assisted editing workflow in which the user can describe changes to existing artwork.
   311→   311→
   312→   312→Example:
   313→   313→
   314→   314→> Change the sword from blue to silver, preserve its shape, keep the transparent background, and use no more than 8 colors.
   315→   315→
   316→   316→Provide two modes:
   317→   317→
   318→   318→**Mode A: Image-to-image editing**
   319→   319→
   320→   320→Send the selected image and editing instructions to a compatible image-editing endpoint when the configured provider supports it.
   321→   321→
   322→   322→**Mode B: Guided manual editing**
   323→   323→
   324→   324→When image editing is unavailable, use the AI response to generate structured instructions, such as:
   325→   325→
   326→   326→- Suggested replacement colors.
   327→   327→- Palette mappings.
   328→   328→- Pixel coordinates or bounded edit regions.
   329→   329→- Layer creation instructions.
   330→   330→- Step-by-step manual editing suggestions.
   331→   331→
   332→   332→Do not falsely claim that a text-only model has edited an image.
   333→   333→
   334→   334→Preserve the original artwork and apply changes to a duplicate layer or a new document unless the user explicitly chooses otherwise.
   335→   335→
   336→   336→### 5.3 AI-assisted creation from structured output
   337→   337→
   338→   338→Where possible, support models or services that return structured pixel data.
   339→   339→
   340→   340→For example, allow a compatible model to return a JSON array of palette indices or a compact representation of a sprite. Validate dimensions, palette indexes, and data length before importing.
   341→   341→
   342→   342→Treat structured pixel data as an optional advanced capability, not a requirement for every AI provider.

   344→   344→## 6. Universal AI Provider Configuration
   345→   345→
   346→   346→The user must supply their own API configuration.
   347→   347→
   348→   348→Do not hardcode an OpenAI API key or make a proprietary provider mandatory.
   349→   349→

   356→   356→- API key.
   357→   357→- Text model identifier.
   358→   358→- Image-generation model identifier.
   359→   359→- Image-editing model identifier.
   360→   360→- Optional organization or project identifier.
   361→   361→- Request timeout.
   362→   362→- Maximum retry count.
   363→   363→- Custom request headers, if enabled safely.
   364→   364→- Test Connection button.
   365→   365→- Save Configuration button.
   366→   366→- Provider capability detection.
   367→   367→
   368→   368→Allow multiple saved provider profiles.
   369→   369→
   370→   370→Support localhost and private-network endpoints, including services hosted on the same computer.
   371→   371→
   372→   372→Examples of configurable endpoints may include:
   373→   373→
   374→   374→- OpenAI-compatible hosted APIs.
   375→   375→- Local OpenAI-compatible inference servers.
   376→   376→- Self-hosted image-generation services.
   377→   377→- Other services implementing compatible chat or image endpoints.
   378→   378→
   379→   379→Do not assume all OpenAI-compatible APIs support image generation. Detect capabilities independently.
   380→   380→
   381→   381→### 6.2 Provider adapter architecture
   382→   382→
   383→   383→Build a provider-independent architecture.
   384→   384→
   385→   385→Suggested TypeScript interfaces:
   386→   386→
   387→   387→```typescript
   388→   388→interface AIProviderConfig {
   389→   389→  id: string;
   390→   390→  name: string;
   391→   391→  baseUrl: string;
   392→   392→  apiKey?: string;
   393→   393→  textModel?: string;
   394→   394→  imageModel?: string;
   395→   395→  editModel?: string;
   396→   396→  timeoutMs: number;
   397→   397→}
   398→   398→
   399→   399→interface AIProviderCapabilities {
   400→   400→  chat: boolean;
   401→   401→  imageGeneration: boolean;
   402→   402→  imageEditing: boolean;
   403→   403→  imageInput: boolean;
   404→   404→  structuredOutput: boolean;
   405→   405→  streaming: boolean;
   406→   406→}
   407→   407→
   408→   408→interface PixelArtAIProvider {
   409→   409→  testConnection(): Promise<ConnectionTestResult>;
   410→   410→  getCapabilities(): Promise<AIProviderCapabilities>;
   411→   411→
   412→   412→  generateImage(
   413→   413→    request: ImageGenerationRequest
   414→   414→  ): Promise<GeneratedImageResult>;
   415→   415→
   416→   416→  editImage?(
   417→   417→    request: ImageEditRequest
   418→   418→  ): Promise<GeneratedImageResult>;
   419→   419→
   420→   420→  chat?(
   421→   421→    request: TextGenerationRequest
   422→   422→  ): Promise<TextGenerationResult>;
   423→   423→}
   424→   424→```
   425→   425→
   426→   426→Adapt the interfaces and request types to the chosen implementation.
   427→   427→
   428→   428→Implement a shared provider interface with separate adapters for chat completion, image generation, and image editing. A provider may implement only some of these features.
   429→   429→
   430→   430→### 6.3 API compatibility
   431→   431→
   432→   432→Support, where applicable:
   433→   433→
   434→   434→- OpenAI-compatible `/v1/chat/completions`.
   435→   435→- Compatible image-generation endpoints.
   436→   436→- Compatible image-editing endpoints.
   437→   437→- Configurable model names.
   438→   438→- JSON responses containing base64 image data or image URLs.
   439→   439→- Data URLs where returned by the provider.
   440→   440→- Streaming text responses when supported.
   441→   441→
   442→   442→Do not assume a single response schema across all providers. Use explicit adapters and validate incoming responses.
   443→   443→
   444→   444→Provide an extensible adapter system for future providers.
   445→   445→
   446→   446→### 6.4 Local and remote AI
   447→   447→
   448→   448→The application must function in three configurations:
   449→   449→
   450→   450→1. **Manual-only mode:** No AI configuration required.
   451→   451→2. **Local AI mode:** Connect to a model or image-generation server running on localhost or a private network.
   452→   452→3. **Remote AI mode:** Connect to a user-configured API endpoint with an optional API key.
   453→   453→
   454→   454→Allow users to disable external network access for AI features.
   455→   455→
   456→   456→Do not send artwork, prompts, telemetry, or project data to any external service unless required for an explicitly requested operation.
   457→   457→
   458→   458→### 6.5 API security
   459→   459→
   460→   460→Implement the following:
   461→   461→
   462→   462→- Store API keys in Windows Credential Manager or another suitable OS-backed secure storage mechanism.
   463→   463→- Never embed API keys in frontend source code.
   464→   464→- Never log API keys.
   465→   465→- Mask API keys in the UI.
   466→   466→- Never include API keys in exported project files.
   467→   467→- Allow users to remove saved credentials.
   468→   468→- Validate endpoint URLs.
   469→   469→- Show clear errors for authentication failures, unsupported models, rate limits, network errors, and malformed responses.
   470→   470→
   471→   471→Use the desktop backend as the secure boundary for sensitive credentials and network requests where practical.

   626→   626→## 11. Performance Requirements
   627→   627→
   628→   628→The application should remain responsive during ordinary drawing and image editing.
   629→   629→
   630→   630→Requirements:
   631→   631→
   632→   632→- Avoid rerendering the entire React interface for every pixel.
   633→   633→- Keep drawing operations inside a dedicated rendering layer.
   634→   634→- Use efficient pointer event handling.
   635→   635→- Use request coalescing or appropriate stroke batching.
   636→   636→- Implement dirty-region redraws where beneficial.
   637→   637→- Use image buffers and efficient layer compositing.
   638→   638→- Move expensive image-processing operations off the UI thread or into the backend.
   639→   639→- Use background workers for quantization and large image conversions when appropriate.
   640→   640→- Provide progress feedback for lengthy operations.
   641→   641→- Handle high-DPI displays correctly.
   642→   642→- Avoid unbounded undo-history memory consumption.
   643→   643→- Gracefully handle unsupported image dimensions and insufficient memory.
   644→   644→
   645→   645→Start with reliable performance on common sprite sizes, including 16×16, 32×32, 64×64, 128×128, and 256×256.

   686→   686→## 13. Privacy, Safety, and Reliability
   687→   687→
   688→   688→- Manual editing must remain available when AI services fail.
   689→   689→- Handle timeouts, cancellations, and connection failures gracefully.
   690→   690→- Validate file contents before importing.
   691→   691→- Limit unreasonable image dimensions and memory allocations.
   692→   692→- Sanitize imported filenames.
   693→   693→- Avoid executing imported project content.
   694→   694→- Prevent accidental project data loss.
   695→   695→- Clearly distinguish local processing from remote AI processing.
   696→   696→- Make telemetry disabled by default unless explicitly configured.
   697→   697→- Never expose API keys in logs, crash reports, or project files.
   698→   698→- Document which AI operations transmit data to a remote provider.
